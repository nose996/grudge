# 记仇 · PVP 交手记录

《魔兽世界："无限"》插件（客户端 1.60.1 / Interface 16001）。自动记录**谁杀过你**、**你杀过谁**，形成可搜索、可标记、可导出的名单。

当前版本 **2.1.25**。代码分两个文件：`Core.lua`（记录与数据）和 `UI.lua`（界面），互不依赖对方的内部实现，只通过 `ns.*` 接口通信。

## 安装

把整个 `Grudge` 文件夹放进：

```
D:\wow\World of Warcraft\_forever_\Interface\AddOns\
```

```
_forever_\Interface\AddOns\Grudge\Grudge.toc
_forever_\Interface\AddOns\Grudge\Core.lua
_forever_\Interface\AddOns\Grudge\UI.lua
```

重启客户端，在角色选择界面的「插件」列表里确认 `记仇 · PVP 交手记录` 已勾选。

## 怎么打开

**不用敲命令**：小地图边上有枚金框的「仇」字按钮。

- **左键**：打开 / 关闭名单
- **右键**：打开设置面板
- **按住左键拖动**：沿小地图圆环挪位置，松手即保存

名单窗口右上角还有「设置」「日志」两个小按钮。

## 界面

整套界面只用两样东西搭：**色块**和**1px 细线**（设置面板的开关也一样，没有圆角贴图可用，所以开关是方块而不是胶囊）。这版客户端不吃外部贴图（INV_* 图标会渲染成红包，UI-* 素材直接不显示），所以没有浮雕、没有金属边，走的是暗底 + 金色细线 + 一个强调色（金 #d8b46a）的路子，信息层级靠字色区分：金色=强调、暖白=正文、灰=次要。按钮全部扁平化，悬停提亮边框，按下加深——主窗、日志窗、导出窗、设置面板四个窗口用的都是这一套自绘按钮（模板按钮的木纹九宫格在本服盖不掉，只能自己画），底色也统一盖了一层很淡的暖棕，不再是原生那层冷黑木框。

**名单窗口**：两个页签（杀过我的 / 我杀过的）+ 名字搜索，按 星标 → 次数 → 最近时间 排序。点一行看详情：标星、忽略、写备注、删除。底部两行统计：上面一行是「今天 X 杀 Y 死 · 本周 X 杀 Y 死」（按本周一 0 点切分，现算不占存档），下面一行是总击杀 / 总死亡 / 名单人数。

**鼠标提示**：鼠标划过或选中一个玩家时，如果他在名单里，提示框末尾会自动多出一行交手记录——「你杀过他 3 次 · 他杀过你 1 次 · 上次 3 天前 · 荆棘谷」，带星标的会加★，写过备注的会跟一行备注。不用开名单就能认出对面是谁。

**仇人接近提示**：名单里的人出现在你视野内（姓名板范围）时，除了聊天框一行字，还会**在屏幕中央偏上弹一条红色横幅**——「仇人接近 XX（杀过你 3 次）」，重点目标带金色★，0.15 秒淡入、停 2.8 秒、0.85 秒淡出，出现瞬间屏幕四边还会**闪一圈红晕**（1.9 秒退干净），同时**播一声提示音**（音源可选，见下）。打架的时候聊天框根本顾不上看，这条横幅才是真正管用的提示。120 秒冷却，同一个人不会一直刷。声音和屏幕提示可以分别关掉。**音源与声音的坑（2026-11-20 排查定案）：** 本服插件出声只有三种写法有效——`PlaySound(编号)`、`PlaySoundFile(数字 FileDataID)`、`PlaySoundFile("Interface\AddOns\<插件>\x.wav")`。而 `Sound\...` 这类系统素材**字符串路径**会被客户端静默丢弃：调用不报错、`pcall` 返回成功、就是不出声，参数个数和通道名都与此无关。默认音源是**亡灵号角**（FileDataID 567386，NPCScan 旧版那声），另有战鼓 / 雷劈 / 巫妖王语音 / 自带 beep 可选，`/kl snd` 挨个试、`/kl snd <序号>` 定下来。

**最终实测结论（2026-11-20，逐个试听确认）：** 本服插件出声有三条路——①`PlaySound(编号)` 走客户端内部音效库（856/852/799 实测都能响，但听感是 UI 点击音，插件里已移除）；②`PlaySoundFile(数字 FileDataID)` 走客户端文件表（SilverDragon 播稀有精英提示音就是这一路，`LSM:Register("sound", "War Drums", 567275)` 之后 `PlaySoundFile(567275, "Master")`）；③`PlaySoundFile("Interface\\AddOns\\<插件>\\x.wav")` 插件自带文件。相反，凡是 `Sound\\...` 这类 **系统素材字符串路径**（猫叫哨 ogg、AlarmClockWarning3.wav、igMainMenuOptionCheckBoxOn.wav）**一律静默**，调用不报错但不发声。所以要么用数字 ID，要么自带文件，绝不能写 `Sound\\` 路径。

**顶部敌情条**：横幅只闪 3.8 秒，低头按技能的工夫就过去了。所以另有一条常驻的：**只要仇人的姓名板还挂在你视野里，屏幕上方就一直有一小条**——「■ 敌情 ★某某 5 · 某某 2」，最多并列 4 个，多的写「另 N 人」；重点目标带金色★。他血条消失（走开或者死了）条立刻收起，视野里一个仇人都没有时整条隐掉。不用打字、不用开窗口，抬头就在。设置面板里能单独关。
**设置面板**：按用途分成三组，一屏看完不用滚（300 × 440）。`提醒` 组放附近仇人提醒、接近时提示音、接近时屏幕提示、顶部敌情条；`显示` 组放小地图按钮、悬停显示交手记录；`排查` 组放调试输出。每组都是**一行一个开关，开关固定贴在右侧**，开是金底「开」、关是暗底「关」，整行都能点，不用瞄着小方块按。下面是 `工具` 区六按钮：日志窗、导出名单、**复制诊断**（弹小窗，里面有版本、接口状态、名单人数，全选复制就能贴给作者）、换个提示音、清理脏数据、清空名单（暗红字，点两次确认，3 秒后自动还原）。底部一行是名单人数和累计战绩，右下角是版本号。

**日志窗**：独立的记录流水，只显示本插件自己的动作——谁被记为击杀、谁被记为死亡、名字什么时候补全、哪条被当成 NPC 丢掉，带时间和颜色（绿=击杀，红=死亡，橙=警告，灰=调试）。可拖动、可清空、可导出。最多留 400 条，窗口关掉后仍在后台记录。

**导出窗口**：名单或日志导出成纯文本，`Ctrl+A` 全选 `Ctrl+C` 复制，可直接贴到群里或攻略站。

## 工作原理（重要）

这版客户端把战斗日志封得比想象中更彻底：不只是 `COMBAT_LOG_EVENT_UNFILTERED` 和 `CombatLogGetCurrentEventInfo` 被移除（注册就弹「该功能只对暴雪的UI开放」并禁用插件），连聊天窗口里那些「你的 瞄准射击 命中 XXX」的**消息事件本身**也全部注册不上——`CHAT_MSG_COMBAT_SELF_HITS`、`SELF_SPELLS`、`PET_HITS`、`PET_SPELLS` 实测全是 false。你在聊天框能看见那些字，是客户端自己渲染的，插件一条都收不到。

所以本插件走的是这条链路：

1. **`PARTY_KILL`**（可注册）—— 最稳的一路。实测这服的参数形态是**「击杀者 GUID + 受害者 GUID」两段**（杀怪时第二段是 `Creature-`），配合姓名板缓存就能换出受害者的「名 姓」；**杀灰名小号（没荣誉、不计 PVP 击杀）也能记上**，因为这条事件根本不看荣誉。**判定只有一条：第一段 Player GUID 不是我本人，整条丢弃**——队友、路人不做区分，反正不是我的击杀就别记到我头上（2.1.22 起）。以前是把「第一个不是我自己的 Player GUID」当受害者，结果队友击杀了谁，受害者就是他队友本人，整份名单被两个同队玩家刷了 31 条。只有一个参数时无法判断谁是击杀者，那段只能当受害者处理（兼容老形态）。宝宝或召唤物补最后一刀时参数会退化成 `Creature-` / `Pet-` GUID，拿不到名字，这时交给下一条。
2. **姓名板缓存**（`NAME_PLATE_UNIT_ADDED` / `NAME_PLATE_UNIT_REMOVED`）—— 玩家进入姓名板范围时记下完整「名 姓」、GUID、等级；血条消失时记下消失时刻。**玩家被打死血条就会消失**，所以触发后去查 15 秒内消失的那个 `Player-` 单位，多半就是刚被放倒的人。注意「血条消失」也可能是走出范围，所以这条只提供候选，最终由 GUID 判据和去重把关。
3. **`PLAYER_PVP_KILLS_CHANGED`**（可注册）—— 只在**有荣誉的击杀**上触发，而且触发得晚，事件到达时 `target` 通常已被清空（实测日志里一直是 `目标=nil`）。它本身不带名字。**2.1.22 起它不再写名单**：这个计数器会被队友战果带偏，触发时又拿不到是谁，早前用它去猜「最近命中过的人」，把只打了几枪并没打死的人记成了自己的击杀（2.1.17 实机踩过）。现在它只负责在日志里留一条「发生了 PVP 击杀，但没确认是谁」的痕迹，真要补记就 `/kl add 名字`。
4. **推断兜底已全部删除（2.1.24）** —— 2.1.11 到 2.1.23 一直保留着两条「猜」：`target` / `mouseover` / `focus` 上选着「已死且姓名板刚消失的玩家」算受害者；以及姓名板刚从视野里消失的玩家也算受害者。两条都靠不住：3v5 混战时敌方五个人来回穿梭，谁跑远、谁倒下、谁隐身都会被记成自己杀的（实测一场把 Leung Bao 记了 3 次，而同一时刻日志还在报「附近出现 Leung Bao」和「你已死亡」）。现在**参数里没有受害者的 `Player-` GUID 就当场跳过**，不做任何推断。代价是宠物/宝宝补最后一刀会漏记。
5. **`CHAT_MSG_COMBAT_HONOR_GAIN`** —— 本服只发「你获得了 X 点荣誉」，模板里没有名字，只能当信号，补不了名字。
6. **`CHAT_MSG_COMBAT_MISC_INFO` / `CHAT_MSG_SYSTEM`** —— 注册得上，但本服从来没广播过「你 杀死了 XXX」，留着备用。
7. **`C_DeathRecap.GetRecapEvents`** —— 死亡回顾，里面记录了对你造成伤害的来源，从中挑出 `Player-` 开头的 GUID，就是杀你的人。记「杀过我的」全靠它，一直很稳。

几条信号同时到达时，按名字做 8 秒去重，不会记成两次。被去重挡下的那次按「这刀已经记过了」处理，不会再当成漏记。

`PARTY_KILL` 如果是宝宝/宠物补的最后一点伤害，参数里会退化成 `Creature-` / `Pet-` 的 GUID，拿不到受害者名字——这种情况**直接丢弃，不做任何推断**（2.1.24 起）。这是有意为之：本服没有任何「是我打死的」强信号（CLEU 被封、`SELF_HITS` 注册失败、连「你 杀死了 X」都只在测试环境里存在），任何推断都会把别人的战绩记到自己头上，**漏记比误记好**。

判断「是不是玩家」的硬依据是 **GUID 形状**：`Player-` 开头才算玩家，`Creature-` 是 NPC。名字段数不能当判据——本服玩家都是「名 + 姓」两段，但**插件有时只拿到前一段**（例如「燃烧的精灵」其实是半名，全名还有后半截），半名往往只有一个词、没有空格，用「有没有空格」来判玩家就会把它当成 NPC 丢掉。所以**姓名板建议一直开着**，GUID 和等级都来自姓名板缓存，关掉之后只剩形状猜，被截半的名字很容易漏。

## 数据存在哪

**纯本地文件，服务器不保存**：

```
WTF\Account\<你的账号>\SavedVariables\KillList.lua
```

这个文件是账号级的，但**里面按角色分开存**，结构是 `KillListDB.chars["角色名"].players`，所以同一个账号下的猎人和骑士各有一份自己的名单，互不干扰。窗口右下角会显示当前是哪个角色的名单。

老版本（2.0.x 及更早）的存档是账号级一整份，第一次加载新版时会自动并进当时登录的那个角色名下，原数据不会丢。

写得进的时机是正常退出游戏或 `/reload`，游戏崩溃的话最近一段记录会丢。

- 更新插件、删掉 `AddOns\Grudge` 重装 → **不会丢**（数据在 `WTF` 下，和插件目录分开）
- 换电脑、重装客户端、删掉整个 `WTF` → **会丢**，除非把这个 `.lua` 单独备份

**迁移到新电脑**：把 `SavedVariables\KillList.lua` 拷到新机器的同样位置（`SavedVariables` 文件夹不存在就自己建一个）。进游戏用 `/kl stats` 核对总数，对得上就说明成功了。

## 功能

- 双页签 + 名字搜索，按 星标 → 次数 → 最近时间 排序
- 单条详情：标星、忽略、写备注、删除
- 同一人 10 分钟内放倒你 3 次，聊天框红字提醒「可能正在守尸」
- 仇人出现在附近会提示一次（120 秒冷却），可关闭
- 一键导出纯文本、独立日志窗、小地图按钮、设置面板
- 调试输出默认关闭，需要时在设置面板或 `/kl debug` 打开

## 已知限制

1. **名字经常只拿到一半**：这版没有 realm，玩家名是「名 + 姓」两段（例如「极道王 夺心魄」），但不同接口给的段数不一样——`UnitName` 往往只给前一段，`GetUnitName(unit, true)` 才给全名。只拿到前一段时，名单里显示的就是「燃烧的精灵」这种半名。插件依次试探四个接口取最长的那版；后续再拿到全名时自动升级已有条目并保留击杀次数。
2. **等级 / 职业靠缓存**：对方要出现在姓名板范围内才拿得到，没见过的显示「等级未知」。判断「是玩家还是 NPC」也依赖这份缓存里的 GUID，所以姓名板别关。关着时退一步用「名字里有没有空格」来猜，只拿到半名的玩家会被漏掉。
3. **死亡回顾可能为空**：客户端在死亡瞬间不提供回顾数据时，`/kl debug` 会打印「死亡回顾里没有找到玩家来源」，这时只能靠人工补记。
4. **宠物杀人**：宠物杀死你时，回顾里只有宠物名，无法反查主人。

## 排查

先看**日志窗**（`/kl log` 或名单窗口右上角「日志」）。哪条被记上、哪条被丢掉、为什么丢，都按行滚出来。

再看 **`/kl env`**，一次看清各信号是否可用：命中消息、法术命中、宠物命中、宠物法术在本服一直是 false，PVP 击杀数、姓名板移除、选中变化应该是 true。

如果真出问题，日志里会打印这几行，把它们发出来即可定位：

- `PARTY_KILL 没拿到受害者，1 秒内再补两次` —— 参数里只有 `Creature-` / `Pet-`，宝宝或 DOT 补的最后一刀
- `丢弃 NPC 击杀：「xxx」（姓名板从没见过）` —— 等过 1 秒缓存里仍然没有这个人
- `PVP 事件没记新记录（多半这刀已记过）` —— 正常现象，多半是 `PARTY_KILL` 已经先记了
- `死亡回顾里没有找到玩家来源`
- `[记仇 拦截] 插件 Grudge 调用了受限函数：xxx`
